# Roadmap · 拍摄策划工作台

> 起点：**v1.0.0**（2026-10-04）
> 定位已确定：**先做离线工作台**。离线、选项卡 + 文本输入式编辑为主，
> 导出到在线资料库是添头，不是主要矛盾。

---

## 版本哲学

这个工具的取舍是**「少而完整」优于「多而半成品」**。因此：

- **v1.x** 只解决「把策划案写清楚、导出成能给人看的文档」
- **v2.x** 才解决「数据跟着人走」
- **v3.x** 才是「多人协作」

宁可 v1.0 的导出通道做好，也不要 v1.0 里塞 6 个半成品功能。

## v1.1 — 导出通道（0.5–1 人日）

> **优先级最高。** 这是 v1.0.0 唯一的功能性缺口。

### PDF 导出

现状是浏览器打印，版式可用但不够可控。加一条「导出 PDF」按钮，
用 `window.print()` + 预设 `@page` 参数，让用户一键拿到 A4 版式。

**技术路径**：不引库。`window.print()` 已能满足，加预设打印样式即可。

### DOCX 导出

**技术选型已完成**：GitHub 上唯一全项过关的方案是
[`dolanmiu/docx`](https://github.com/dolanmiu/docx)。

但它是 npm 包，**与「单文件零依赖」冲突**。三个方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 内联docx 库 | 把压缩后的 docx.js 内嵌进 HTML | 体积 +800 KB；许可需核|
| B. 导出 HTML 后转| 导出一个 Word 可打开的 HTML | 体积 0；但格式控制弱，非真 DOCX |
| C. 双击即用 + 可选增强 | 默认走浏览器打印；检测到有 npm 时用 A | 复杂度高 |

**待你拍板**（原本的 Q2，现已不重要——v1.1 阶段再定即可）。

## v2.0 — 存储加固（0.5 人日）🔺 建议提前到 v1.1

> **原本排在这里，但实测数据表明风险已经发生了。**

### 为什么要提前

本机实测结论（Playwright 探针，2026-10）：

| 事实 | 数值 |
|---|---|
| localStorage 上限 | **4.94 MB** |
| 单张压缩图 | 约 59 KB |
| 单个满配场地（10 图） | 约 593 KB |
| **触顶临界** | **约 6 个满配场地** |

写满 6 个场地后，数据写入会**静默失败**——
用户以为存上了，刷新后全没了。这是**数据丢失级**的问题。

### 要做什么

| 事项 | 说明 |
|---|---|
| 容量指示器 | 顶栏显示已用 / 上限，超过 80% 变黄、95% 变红 |
| 写入 try-catch 降级 | `QuotaExceededError` 时明确报错 + 提示清理，不要静默失败 |
| CSV Injection 防护 | 导出 CSV 时对以 `=` `+` `-` `@` 开头的单元格加前缀 |
| 数字格式提示 | 千分位 / 日期格式变形提醒 |

## v2.1 — 文件系统直写（2–3 人日）

**能力**：改本地 CSV / JSON 文件无需手动选目录，工具直接读写。

**技术**：File System Access API（`showSaveFilePicker` / `showOpenFilePicker`）。

> ⚠️ **仅 Chromium 系支持**（Chrome / Edge / Opera）。
> Firefox 与 Safari **完全不可用**，需降级回「下载全量」。

> **待你拍板（原本的 Q2）**：是否接受 Firefox / Safari 不可用。
> 若接受，则本版对绝大多数用户无影响（摄影场景主力是Chrome）。

### 相比 v2.0 的区别

| | v2.0 | v2.1 |
|---|---|---|
| 写入方式 | 手动下载 + 选目录覆盖 | 工具直接写 |
| 记录策略 | 全量导出 | 按主键 **upsert**（新增/ 更新分开） |
| 冲突处理 | 人工判断 | 按 `updatedAt` 时间戳自动取新 |

## v3.0 — 飞书多维表格同步（4–6 人日）

**能力**：模特库/ 场地库与飞书多维表格双向同步。

### 已确认的硬约束

调研报告第九章的结论：

| # | 结论 |
|---|---|
| 1 | 飞书接口开放，但 **CORS 无法绕过** |
| 2 | → **必须引入一个极薄的本地代理进程** |
| 3 | 附件必须**两段式上传**：先传素材拿 `file_token` → 再写记录 |
| 4 | `file_token` **仅当前表有效**，每图需单独上传 |
| 5 | app_secret 等凭据**不能明文存 localStorage**（泄漏风险） |

> ⚠️ **形态变化**：v3.0 不再是「双击即用的单文件工具」，而是「要起服务」。
> 这是产品形态的改变，不只是加功能。

> **待你拍板（原本的 Q3）**：是否接受引入常驻 Node 进程。

### 前置未查证事项

- 飞书素材上传的**配额限制**未查证（风险登记 R16）——
  多图场景下可能撞配额，v3.0 实施前必须确认
