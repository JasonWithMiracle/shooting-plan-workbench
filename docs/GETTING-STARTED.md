## 为什么会有这个工具

摄影策划的瓶颈从来不是「想创意」，而是**把创意写成一份别人能执行的文档**。

摄影助理要照着打包，模特要照着准备，场地要照着报备。
而这些信息天然散落在微信聊天、备忘录、脑子里。

市面上的两种解法都有问题：

- **Word 模板**：不会算存储卡数，不会检查必填项，填完自己也不知道漏了什么
- **云端SaaS**：要联网，图片要上传服务器，策划案在别人手里

这个工具是第三种答案：**一个 HTML 文件，打开就是全部功能。**

| | Word 模板 | 云端 SaaS | 本工具 |
|---|---|---|---|
| 需要安装 | Word | 浏览器 + 联网 | **无** |
| 离线可用 | ✅ | ❌ | ✅ |
| 图片隐私 | 本地 | **上传服务器** | **本地，不出浏览器** |
| 必填项检查 | 靠人肉 | ✅ | ✅ |
| 存储卡换算 | 手动算 | ✅ | ✅ |
| 费用 | 0 | 订阅制 | **0** |
| 策划案编号唯一 | ❌ 手工填 | ✅ | ✅ 自动分配 |

## 走一个真实案例

场景：**给一位合作过的模特，拍一组古风旗袍写真。**

### 第 1 步 · 建立策划案与编号

打开工具 → **§0 基本信息** → 0.1 点「**分配编号**」。

工具生成 `CX-20261004-01`。这个编号是**只读**的，且是本策划案在目录、台账、成片侧的**唯一主键**。

- 同一天再建案：序号自动递增（`-01` → `-02`）
- 换一天：序号重置
- 填错了：再点一次会**释放**旧号再分配，不占用

### 第 2 步 · 把老模特的档案调出来（省一半时间）

如果这位模特之前合作过，**不用重填**：

1. 先在 §0.7「本场模特姓名」填 `林小雨`
2. 切到 **§1 模特** → 下方「模特库」点「**调入**」

身高、体重、体格特征、样图一次性回填。**因为身体数据是可复用资产。**

> 模特库只存可复用的身体数据。本场专属信息（妆造、租金、档期）留在策划案里。

### 第 3 步 · 场地同理

1. **§4 场地** 填档案 7 要素（名称/ 所在区 / 适配风格 / 是否时效性 / 门票 / 简述 / 参考图）
2. 点「**存入场地库**」，以后去同场地直接「调入」
3. §0.3 的「地点名称」会同步带入

![场地库](../screenshots/05-venue-library.png)

### 第 4 步 · 布光：先选方案类型

**§6.5 布光方案** 第一件事是选模式：

| 方案 | 什么时候用 | 3D 渲染图 |
|---|---|---|
| **严谨** | 商业拍摄、夜拍、需要精确控光 | **必填** |
| **快捷** | 外景记录性拍摄、随手拍 | **整节不显示**，可正常导出 |

选「快捷」后 6.5.3 / 6.5.4 整节消失，**不用填也能导出**。
已填的数据保留，切回严谨可恢复。

![布光](../screenshots/06-lighting.png)

**光位规划**默认只显示「主光」一行，需要更多灯位点「＋ 添加灯位」，
逐行 ✕ 可删。灯位 9 项、光线方向 11 项，都是单选。

### 第 5 步 · 行程：点时段轴排今天的时间

**§7 行程安排** 最有价值的是 7.1 的**时段轴**。

点「**黄金时刻**」或「**日落**」→ 自动设为行程起点。

| 节点 | 典型时间 | 说明 |
|---|---|---|
| 妆造 | 08:30 | 按 §3 参考图定妆 |
| 布光 | 10:00 | 按 §6.5 方案落地 |
| 拍摄 | 12:00 | 对齐 §11 参考样片 |
| **黄金时刻** ★ | 16:30 | 低角度暖光，逆光/剪影最佳 |
| **日落** ★ | 18:30 | 蓝调时刻，日落后 30 分钟内 |
| 收工 | 19:30 | 归还物品、向管理员致谢 |

> ★ 标记的两段是拍摄日**最不可错过**的。
> 具体日落时刻随纬度与日期变化（冬季日落早约 1 小时），**以拍摄地当日实测为准**。

排完在 7.3 看耗时汇总 —— 若与 §0.2 的「预计时长」差超过 10 分钟会给出调整建议。

![行程](../screenshots/12-schedule.png)

### 第 6 步 · 传参考样片，和模特对齐审美

**§11 参考样片** 传 5-25 张（不足 5 张会拦住导出）。

建议覆盖：**色调 / 构图 / 光位 / 妆造 / 服装 / 氛围**。

![参考样片](../screenshots/11-reference-shots.png)

每格右上角 **✕** 可删传错的图，点图可放大。
图片槽统一 4:3 基准格 + 完整显示不裁切，所以宽高比不同的图也能网格对齐。

### 第 7 步 · 打印签署页

**§9 注意事项** 是 5 条活动须知 + 签署确认表（模特、摄影师两行）。

打印或「另存为 PDF」即带走完整须知与签字栏。
需要提前发出去的话，用仓库里的 [`pre-shoot-checklist.md`](../pre-shoot-checklist.md)。

![注意事项](../screenshots/07-notices.png)

### 第 8 步 · 导出

点顶栏「**打印 / 存 PDF**」→ 在打印对话框里把「目标」选成
「另存为 PDF」→ 保存。

打印样式已做处理：深色主题强制转白、删除按钮隐藏、
图片限高 42mm、表格行不跨页断行。

![浅色主题](../screenshots/14-light-theme.png)

> 📌 **DOCX 导出尚未实现**（按钮上标了「未实现」），
> 原因与替代方案见 [已知限制](../README.md#已知限制)。

> 💡 **要留档/ 换设备，请用「⇩ 导出整案」而不是打印**——
> 打印出来的是死文档，恢复不了数据。

## 三处值得知道的设计

### 上传图片是为了排布，导出才是终点

参考图在工具里显示得整齐，**导出到 PDF / DOCX 才是交付物**。
所以图片槽统一 4:3 基准格 + 完整显示，让不同宽高比的图也能网格对齐 ——
一屏看全，导出时版式可控。

### 编号是主键，不是标签

`CX-YYYYMMDD-XX` 由工具分配、只读、跨日重置、释放不撞号。
它是策划案在目录、台账、成片侧的**唯一主键**，
导出文件名、归档目录、台账溯源全以此为准。

### 逼你确认的，只逼真正要确认的

强制项的设计原则是**宁可漏项，不要形式主义**。

比如 §7 行程表，只有「**事项**」非空的行才计入必填 ——
否则点了「＋ 添加时段」还没填内容就被拦，反而是噪音。

## 常见场景速查

| 场景 | 怎么做 |
|---|---|
| 老模特二次合作 | §1 模特库点「调入」 |
| 同场地再拍 | §4 场地库点「调入」 |
| 一次拍两个场地 | §4 存两条档案，§0.3 分开填 |
| 外景随手拍 | §6.5 选**快捷**方案，跳过 3D 渲染图 |
| 需要精控光 | §6.5 选**严谨**方案，6.5.3 渲染图必填 |
| 场地要报备 | §4「是否时效性」选**是** → §10 应急会提示确认档期 |
| 存储卡买多大 | §6.6 填容量，自动出卡数（0.8 安全系数） |
| 算当天要拍多久 | §7.3 耗时汇总，与 §0.2 预计时长比对 |
| 打印带签字栏 | 切「预览」→ 打印；§9 签署表会带上 |
| 换电脑继续填 | 「⇩ 导出整案」→ 在新设备「⇧ 导入整案」 |
| 留个备份防意外 | 「⇩ 导出整案」，建议每次重要拍摄后做一次 |

## 数据管理（重要）

### 数据存在哪

浏览器 **localStorage**，键名：

| 键 | 内容 |
|---|---|
| 策划案 | 全部章节内容 |
| `sw_models` | 模特库 |
| `sw_venues` | 场地库 |
| `sw_usedno` | 已占用的编号 |

**不上传任何服务器**，图片以 base64 存在本地。

### 三个必须知道的后果

1. **关掉浏览器不会丢**（自动保存）
2. **换浏览器 / 换电脑不会自动同步** —— 用「导出整案 / 导入整案」手动带走
3. **清理浏览器数据会丢** —— 请谨慎使用「清除浏览数据」；清理前先导出备份

### 换设备：用「导出整案 / 导入整案」

数据不会自动跟着你走，但**可以手动带走**：

**在旧设备上**：点顶栏「**⇩ 导出整案**」→ 得到一个 `.json` 文件
**在新设备上**：点顶栏「**⇧ 导入整案**」→ 选那个文件 → 二次确认后恢复

备份内容包含：**12 个章节的全部内容 + 模特库 + 场地库 + 编号占用表**。
文件可以直接发微信、存 U 盘、丢进网盘。

> ⚠️ **别用「打印 / 存 PDF」来转移数据。**
> 那份 PDF 是排版好的成品（给人看的），**不能恢复数据**。
> 换设备、备份、重装系统，都要用「导出整案」。

> 💡 建议在**每次重要拍摄结束后**导一次。文件不大（无图时几十 KB），
> 但能省掉「填了 40 分钟结果换电脑丢光」的惨剧。

### 容量上限

实测 **4.94 MB**：

| 内容 | 体积 |
|---|---|
| 单张压缩后图片 | 约 59 KB |
| 单个满配场地（10 图） | 约 593 KB |

→ 约 **6 个满配场地**后触顶。触顶时数据写入会**静默失败**。

> **建议**：场地库控制在 6 处以内。
> 超出后用工具内的 CSV 导出备份，再清理浏览器数据。

### 备份

见上文「换设备：用导出整案 / 导入整案」。

## 常见问题

**导出提示「还有必填项未填」，但找不到缺哪个**
切「**核对**」模式，会高亮所有未填项。

**编号能不能自己改**
不能，这是设计。编号是主键，手改会导致台账与成片对不上。
填错就再点一次「重新分配」。

**图片会被裁掉吗**
不会。图片槽用 `object-fit: contain` 完整显示，与格子比例不符时留白而非裁切。

**§6.3 和 §6.5 都要填灯，重复吗**
不重复。§6.3 登记「带了什么灯」（资产登记），§6.5 规划「灯怎么摆」（布光方案）。
两处信息量不同。

**样图只能传 2 张，参考样片能传 25 张，为什么差这么多**
样图是「选角参考」，2 张够判断尺码与气质；
参考样片是「风格对齐」，需要覆盖多个维度故给到 25 张。

**能多人协作吗**
不能。这是单机工具。多人在同一策划案上协作需等飞书同步（v3.0，优先级最低）。
